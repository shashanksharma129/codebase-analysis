# Codebase Analyzer — Streamlit UI Design Spec

**Date:** 2026-05-31  
**Status:** Approved

---

## Overview

A Streamlit web UI that wraps the existing CLI pipeline. The user pastes a public GitHub repository URL, the app downloads the repo as a ZIP, runs the LangChain analysis pipeline, and displays results in two tabs: a human-readable summary and a raw JSON viewer with download.

**Invocation:**
```bash
streamlit run ui.py
```

## Data Flow

```
App startup
  │
  ▼
load_dotenv() → reads .env
create_llm()  → validates LLM_PROVIDER + API key
  │  fail → catches click.ClickException → st.error + st.stop()
  │
  ▼
User inputs GitHub URL + branch (default: main)
User clicks "Analyze"
  │
  ▼
URL Parser
  - Regex: extract owner, repo, branch from URL
  - Accepts: https://github.com/{owner}/{repo}
             https://github.com/{owner}/{repo}/tree/{branch}
             https://github.com/{owner}/{repo}.git
  - Fail → st.error("Invalid GitHub URL"), stop
  │
  ▼
ZIP Download  (st.status: "Downloading repository...")
  - GET https://github.com/{owner}/{repo}/archive/refs/heads/{branch}.zip
  - Non-200 → st.error("Download failed: HTTP {status}"), stop
  - Network error → st.error(str(exception)), stop
  - Extract to tempfile.mkdtemp()
  │
  ▼
Pipeline  (st.status: "Analyzing {N} domains...")
  - asyncio.run(run_pipeline(source, llm, cache, ext=".java"))
  - try/finally: temp dir always deleted
  - Pipeline error → st.error(str(exception)), stop
  │
  ▼
Results Display
  - Tab 1: Summary
  - Tab 2: Raw JSON
```

## URL Parsing

```python
import re

_GITHUB_RE = re.compile(
    r"https?://github\.com/([^/]+)/([^/]+?)(?:\.git)?(?:/tree/([^/]+))?/?$"
)

def parse_github_url(url: str) -> tuple[str, str, str]:
    """Returns (owner, repo, branch). Raises ValueError on no match."""
    m = _GITHUB_RE.match(url.strip())
    if not m:
        raise ValueError(f"Not a valid GitHub URL: {url!r}")
    owner, repo, branch = m.group(1), m.group(2), m.group(3) or "main"
    return owner, repo, branch
```

ZIP download URL: `https://github.com/{owner}/{repo}/archive/refs/heads/{branch}.zip`

## Error Handling

| Scenario | Behavior |
|---|---|
| `.env` missing or API key unset | `try/except click.ClickException` wraps `create_llm()` at startup; `st.error(str(e))` + `st.stop()` |
| Invalid GitHub URL | `st.error("Invalid GitHub URL — expected https://github.com/owner/repo")` |
| HTTP non-200 on ZIP download | `st.error(f"Failed to download repository: HTTP {resp.status_code}")` |
| Network error | `st.error(f"Network error: {e}")` |
| Pipeline exception | `st.error(f"Analysis failed: {e}")` |
| Empty repo (no .java files) | Pipeline returns empty domains list — Summary tab shows "No domains found" |

All errors stop execution for that run. The input form remains visible so the user can retry.

## Temp Directory Lifecycle

```python
import tempfile, shutil

tmp = tempfile.mkdtemp()
try:
    # extract zip, run pipeline
    ...
finally:
    shutil.rmtree(tmp, ignore_errors=True)
```

The `.cache/` disk cache persists between runs (same behavior as the CLI).

---

## Constraints

- **Public repos only** — no GitHub auth token; private repos return HTTP 404
- **Main branch default** — user can override branch in the UI
- **Java files only** — `ext=".java"` hardcoded in `ui.py`; not user-configurable in the UI (keep it simple)
- **No session persistence** — results are not stored between Streamlit reruns
- **Single concurrent analysis** — Streamlit's single-threaded model; no queue needed for local use

---

## Assumptions & Limitations

- GitHub's ZIP endpoint (`/archive/refs/heads/{branch}.zip`) is public and unauthenticated for public repos
- The extracted ZIP contains a top-level directory named `{repo}-{branch}/`; the pipeline receives that as `source`
- Large repos (>200 files) will be slow — the existing 80k char/domain truncation mitigates token cost but not wall time
